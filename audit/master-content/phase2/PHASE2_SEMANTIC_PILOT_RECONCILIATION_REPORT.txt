SCHEMA CONSISTENCY CHECK -- OPAQUE / NOT_APPLICABLE INVARIANT
==============================================================================
The pilot schema defines taxonomy_status=NOT_APPLICABLE as "used when the
semantic meaning itself is opaque" -- i.e. it should be biconditional with
semantic_status=OPAQUE. Before finalizing, all 500 reconciled rows were
checked against this invariant. 0 rows had OPAQUE without NOT_APPLICABLE.
2 rows had NOT_APPLICABLE without OPAQUE (both semantic_status=PARTIAL):

  fold_key: unusedbone_3b item_ffx_x-2_rikku_by_xxkammyxx
  exact_spellings: unusedbone_3B item_FFX_X-2_Rikku_By_xXKammyXx
  semantic_status (before/after): PARTIAL / PARTIAL (unchanged)
  taxonomy_status (before -> after): NOT_APPLICABLE -> CLEAR
  reason: a self-declared "unused" generic bone carrying an unrelated
    creator-credit string; it was coded NOT_APPLICABLE because the
    remainder of the literal names no body part -- but the "unused"
    self-declaration IS semantic content, and per rule 15 that content
    alone determines a taxonomy destination (Useless) regardless of
    whether the rest of the literal is anatomically legible.
  valid under the intended schema: NO -- taxonomy_status=NOT_APPLICABLE
    is defined for opaque semantic meaning; PARTIAL semantic content that
    is actually sufficient to answer the taxonomy question (self-declared
    unused -> Useless) must never be coded NOT_APPLICABLE.

  fold_key: unused duplicate duplicate unused.006
  exact_spellings: unused duplicate duplicate unused.006
  semantic_status (before/after): PARTIAL / PARTIAL (unchanged)
  taxonomy_status (before -> after): NOT_APPLICABLE -> CLEAR
  reason: a self-declared duplicate/unused placeholder with no anatomical
    content; same defect as above -- the "unused"/"duplicate" declaration
    is sufficient semantic content to answer the taxonomy question.
  valid under the intended schema: NO -- same reasoning as above.

DETERMINED INVARIANT: option A. semantic_status=OPAQUE must always imply
taxonomy_status=NOT_APPLICABLE, AND taxonomy_status=NOT_APPLICABLE must
always imply semantic_status=OPAQUE -- with no legitimate exception. There
was no case here where NOT_APPLICABLE legitimately coexists with CLEAR or
PARTIAL; both violations were genuine miscodings (rule 15's Useless
destination was simply never applied to these 2 rows during the original
pilot pass), not a case calling for a documented exception (option B).

CORRECTION APPLIED: both rows' taxonomy_status was changed to CLEAR,
proposed_destination set to groupFile/Useless (a valid current Master
path), confidence raised to High, uncertainty_reason cleared, and
short_reason updated to record the Useless rationale -- via a second
deterministic pass (fix_schema_invariant.py) against
PHASE2_SEMANTIC_PILOT_500_RECONCILED.tsv only. PHASE2_SEMANTIC_PILOT_500.tsv
(the original) was not opened for writing at any point in either pass.
PHASE2_SEMANTIC_BATCH_RULES.txt rule 15 was broadened to state explicitly
that the self-declared unused/duplicate rule applies even without
anatomical legibility, and a new rule 21 was added stating the
OPAQUE/NOT_APPLICABLE invariant as a standing, mechanically-checkable
requirement for every future batch.
