6. PRECEDENT-INTEGRITY CHECK / CROSS-TRANCHE FINDING (Section 22/23)
============================================================

While classifying "fringe 4" (P81, position 8544) against the corpus's
"fringe" family, a decisive pre-existing error was discovered
incidentally: four earlier-production rows (fringe 1, fringe 6,
fringe 20, fringe 17 jb -- from Tranches 1, 5, 5, and 4 respectively,
batches P03/P46/P42/P30) had been classified PARTIAL/NEEDS_CONTEXT on the
theory that "fringe" is a genuinely ambiguous multi-sense word (hair
bangs vs. decorative garment trim) with no disambiguating content. A
direct grep of the live canonical Master (sfm_defaultanimationgroups.txt)
found an extensive, unambiguous, 100%-consistent bare-word template
precedent: bip_fringe/bip_fringe1/3-8 (lines 43571-43578), Fringe0
through Fringe10 (lines 48125-48145), HairFringeFront/Left/Right
(lines 55196+), HairFrontFringeALeft (lines 55417+), skin_fringe_C_*
(lines 59099+), and "hair fringe left/middle/right" (lines 62020+) -- all
confirmed groupFile/Hair via the structural parser, with zero
counter-example of "fringe" as a decorative-trim reading anywhere in the
Master. This is Authority-order tier 4 (direct live-Master template
precedent), which outranks the unsupported "materially different core
senses" assumption the original four rows were built on -- that
assumption was never checked against the Master itself.

Per Section 23, this was corrected narrowly (only these 4 rows, found
incidentally, not via a broader retrospective audit):

  fringe 1      (originally batch P03): PARTIAL/NEEDS_CONTEXT/blank
                -> CLEAR/CLEAR/groupFile/Hair
  fringe 6      (originally batch P46): PARTIAL/NEEDS_CONTEXT/blank
                -> CLEAR/CLEAR/groupFile/Hair
  fringe 20     (originally batch P42): PARTIAL/NEEDS_CONTEXT/blank
                -> CLEAR/CLEAR/groupFile/Hair
  fringe 17 jb  (originally batch P30): PARTIAL/NEEDS_CONTEXT/blank
                -> CLEAR/CLEAR/groupFile/Hair

Evidence: sfm_defaultanimationgroups.txt lines 43571-43578, 48125-48145,
55196-55207, 55417-55421, 59099-59107, 62020-62045 (verified via the
structural parser in tools/validate_master.py's parse_structure
function, cross-checked against each control's resolved full_path).
The original raw batch files (P03/P30/P42/P46) are NOT rewritten --
they remain the immutable historical record of the original
classification; only the current ledger's authoritative fields were
corrected, with each row's short_reason updated to document the
correction and the original batch_id preserved for provenance.

This correction resolves the ambiguity for these 4 rows only. It does
not generalize to a "fringe is always Hair" rule for any future novel
compound (e.g. a hypothetical "belt_fringe" or "curtain_fringe" literal
would still need its own semantic judgment) -- it specifically applies to
the bare "fringe"/"fringe_N" template that the Master itself
demonstrates is a hair-bangs convention in this corpus.

No other precedent-integrity issues were found. Every "matches sibling
X" claim used in this tranche's short_reason fields was mechanically
re-verified against the current ledger's authoritative fields at
classification time (not against memory, old raw batch files, or old
tranche reports), consistent with Section 3.
